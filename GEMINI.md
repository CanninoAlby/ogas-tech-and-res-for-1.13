## 1. Active Learning Log

### Strict Upgrade Audit for all Production Method Groups (PMGs)
* **Problem / User Constraint:** The `PM_upgrade` system should **only** manage Production Method Groups where successive stages strictly and linearly increase the output of goods. If a PMG does not have strictly increasing outputs (e.g. outputs stay flat, decrease, or are all zero), managing it as a strict one-way upgrade causes major in-game economic errors.
* **Audit Methodology & Discoveries:**
  1. We ran a programmatic audit across all PMGs currently classified as `upgrade`.
  2. We discovered that multiple groups did not satisfy the strict increasing output rule:
     - **Flat/Decreasing output:** `pmg_entertainment_type` (Stage 3 `modern_productions_pm` produces 25 `elgar_music`, but Stage 4 `silent_films` decreases to 15) and `pmg_amenities` (Stage 5 `pm_shopping_centers` and Stage 6 `pm_digital_retail` both produce flat 35 `services`).
     - **0 direct output goods (modifiers/utility/labor-saving groups):** `pmg_base_building_hydroponic_type`, `pmg_elgar_ballet_school`, `pmg_urban_clergy`, and others.
  3. These non-increasing PMGs are fundamentally labor-saving, utility-based, or ratio-balancing choices, rather than linear output upgrades.
* **Solution Implemented:**
  1. We automatically reclassified all non-strictly-increasing PMGs from `upgrade` to `balance` in both `Victoria3 building PM/victoria3_building_pm_goods.csv` and `OGAS script generator/pm_goods.csv`.
  2. This successfully left **exactly 8 PMGs** as strict `upgrade` types (e.g., base glassworks, software industry, rye farms, wheat farms, steelmaking, textiles, airports, and communication).
  3. Regenerated scripts: Balance PMGs generated by OGAS increased from `29` to `38`, and Upgrade PMGs decreased from `17` to `8`. All files were successfully compiled and deployed to `common/`.


### The Food Industry Balance Upgrade (From Upgrade to Balance PMG)
* **Symptom / Logic Flaw:** The base production method group for food industries (`pmg_base_building_food_industry`) was categorized as an `upgrade` type in the CSV files. Because of this, once the technologies (like `distillation`, `baking_powder`, `fast_food`) were unlocked, the OGAS system would permanently force buildings to transition forward to `pm_sweeteners`, `pm_baking_powder`, and `pm_ultraprocessed_snacks` without the ability to downgrade.
* **Root Cause & Economic Risk:** 
  1. Unlike linear technological upgrades, these food industry base production methods require vastly different resource inputs (e.g. `pm_bakery` only needs grain; `pm_sweeteners` and `pm_baking_powder` need sugar; `pm_ultraprocessed_snacks` requires both sugar and electricity).
  2. If a country suffers from extreme sugar shortages or lacks electricity, switching permanently to these "advanced" PMs makes the building highly unprofitable, causing massive bankruptcy in the food sector.
  3. However, since the group was classified as `upgrade` in the CSV, the in-game script (`AUTO_PM_upgrade.txt`) offered no path to revert to simpler methods.
* **Solution:**
  1. We modified the `type` field for all 4 PMs under `pmg_base_building_food_industry` from `upgrade` to `balance` in both CSV files (`Victoria3 building PM/victoria3_building_pm_goods.csv` and `OGAS script generator/pm_goods.csv`).
  2. Running the filter (`node tools/csv_filter.js`) and OGAS generator (`py OGAS script generator/main.py`) automatically migrated the group into `AUTO_PM_balance.txt`.
  3. The building will now dynamically switch between `pm_bakery`, `pm_sweeteners`, `pm_baking_powder`, and `pm_ultraprocessed_snacks` back-and-forth based on real-time prices of grain, sugar, and electricity!


### The Government Administration Downgrade Bug
* **Symptom:** Government Administration buildings are automatically and permanently forced back to the most basic production method (`pm_simple_organization`), even when advanced PMs are unlocked.
* **Root Cause:**
  1. OGAS balances PMs based on a predicted profit value.
  2. In Victoria 3 database and the generated scripts, input goods (like paper, telephones, computers) are represented as **negative numbers** (e.g., `pm_horizontal_drawer_cabinets_paper = -10`).
  3. The profit prediction multiplies this negative quantity by the positive market price, yielding a **negative profit value** (e.g. `-300`).
  4. Since Government Administration is a government service, it produces Bureaucracy/Taxation Capacity (which are not market goods and have no price), so **revenue is exactly 0**.
  5. The profit prediction of the base PM (`pm_simple_organization`) is hardcoded to exactly **`0`** since it consumes no inputs.
  6. The balancing comparison `0 > -300` is always **true**, so the script continuously forces a downgrade.

## 2. Config & Custom Balancing Rules

To prevent this issue and optimize the mod, we rewrote the filter script: [tools/csv_filter.js](file:///C:/Users/axioo/Documents/Paradox%20Interactive/Victoria%203/mod/ogas%20tech%20and%20res%20for%201.13/tools/csv_filter.js).

### The Precise Balancing Rule
A building is included in the OGAS automated balancing loop **only** if it has at least one Production Method Group (PMG) that:
1. Produces at least **2 distinct output goods** (excluding mod-added `raw_data` and `organized_data` optimization goods).
2. Actually **changes the ratio (balance)** of these output goods when switching between PMs.
   * *Formula:* For any pair of PMs and any two output goods $g_1, g_2$, the balance changes if:
     $$v_{1,1} \cdot v_{2,2} \neq v_{1,2} \cdot v_{2,1}$$

## 3. Workflow & How to Regenerate Mod Scripts

If you add new buildings or production methods to the mod and want to apply the configuration, follow these exact terminal commands:

1. **Filter Config:** Run the custom filter script to clean the CSV and identify true balancing buildings:
   ```powershell
   node tools/csv_filter.js
   ```
2. **Regenerate Scripts:** Run the Python script generator (specify UTF-8 environment variable to prevent Windows console encoding errors):
   ```powershell
   $env:PYTHONIOENCODING="utf-8"
   py OGAS script generator/main.py
   ```
3. **Deploy Scripts:** Run the deployment script to copy the newly generated files into the mod's game folders:
   ```powershell
   node tools/apply_generated_scripts.js
   ```
